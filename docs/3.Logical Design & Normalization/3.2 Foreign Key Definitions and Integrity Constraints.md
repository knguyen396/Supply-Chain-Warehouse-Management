3.2.1 Foreign Key Definitions

Foreign keys maintain referential integrity between related tables. Each foreign key references an existing primary key in the parent table. 

The foreign key definitions are as follows:

1.SUPPLIER_ORDER.supplier_id references SUPPLIER.supplier_id. 

2.SHIPMENT.source_warehouse_id and SHIPMENT.dest_warehouse_id reference      WAREHOUSE.warehouse_id.

3.INVENTORY.warehouse_id references WAREHOUSE.warehouse_id, and INVENTORY.product_id references PRODUCT.product_id.

4.PRODUCT_STRUCTURE.parent_product_id and PRODUCT_STRUCTURE.child_component_id both reference PRODUCT.product_id.

5.SUPPLIER_ORDER_DETAIL.order_id references SUPPLIER_ORDER.order_id, and SUPPLIER_ORDER_DETAIL.product_id references PRODUCT.product_id.

6.SHIPMENT_DETAIL.shipment_id references SHIPMENT.shipment_id, and SHIPMENT_DETAIL.product_id references PRODUCT.product_id.

7.RESTOCK_ALERT.warehouse_id references WAREHOUSE.warehouse_id, and RESTOCK_ALERT.product_id references PRODUCT.product_id.




3.2.2 Integrity Constraints
The following integrity constraints ensure data accuracy and consistency according to the business rules defined in Phase 1.

1.Domain Constraints:
-  INVENTORY.quantity_on_hand >= 0.
-  PRODUCT_STRUCTURE.quantity_required > 0.
-  SUPPLIER_ORDER_DETAIL.order_quantity > 0.
-  SHIPMENT.source_warehouse_id <> SHIPMENT.dest_warehouse_id.
-  SHIPMENT.estimated_arrival >= SHIPMENT.dispatch_date.

2.Status Constraints:
-  SUPPLIER_ORDER.status must be Pending, Completed, or Canceled.
-  SHIPMENT.status must be Pending, In-Transit, Completed, or Canceled.

3.Business Rule Constraints:
-  A product cannot be its own parent or child component, directly or indirectly.
-  A shipment cannot be completed if the source warehouse has insufficient inventory.
-  When a shipment is completed, the system must update inventory quantities in both the source and destination warehouses.
-  When inventory falls below the product's minimum reorder level, the system must generate a restock alert.

These constraints can be implemented using CHECK constraints, triggers, and other appropriate database mechanisms.
