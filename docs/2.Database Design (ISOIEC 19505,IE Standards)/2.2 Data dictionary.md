# DATA DICTIONARY

## 1. Warehouse

| Attribute Name | Data Type | Key Type | Nullable | Default Value | Description / Business Rules / Constraints |
|---|---|---|---|---|---|
| warehouse_id | VARCHAR(10) | PK | No | None | Unique identifier for each warehouse. |
| warehouse_name | VARCHAR(100) | None | No | None | Name of the warehouse. |
| location_address | TEXT | None | No | None | Physical address of the warehouse. |
| capacity | INT | None | No | None | Maximum storage capacity. Must be greater than 0. |

**Note:** `warehouse_id` is the primary key. Each warehouse must have a unique identifier and a positive storage capacity (`capacity > 0`).

## 2. Product

| Attribute Name | Data Type | Key Type | Nullable | Default Value | Description / Business Rules / Constraints |
|---|---|---|---|---|---|
| product_id | VARCHAR(10) | PK | No | None | Unique identifier for each product. |
| product_name | VARCHAR(100) | None | No | None | Name of the product. |
| unit | VARCHAR(20) | None | No | None | Unit used to measure the product. |
| unit_price | DECIMAL(10,2) | None | No | None | Standard unit price. Must be greater than or equal to 0. |
| min_reorder_level | INT | None | No | 0 | Minimum stock level that triggers a restock alert. Must be greater than or equal to 0. |

**Note:** `product_id` is the primary key. A product can be stored in zero or multiple warehouses. Its `min_reorder_level` must be greater than or equal to 0. When the inventory quantity falls below this level, the system shall create a restock alert.

## 3. Supplier

| Attribute Name | Data Type | Key Type | Nullable | Default Value | Description / Business Rules / Constraints |
|---|---|---|---|---|---|
| supplier_id | VARCHAR(10) | PK | No | None | Unique identifier for each supplier. |
| supplier_name | VARCHAR(100) | None | No | None | Name of the supplier. |
| contact_email | VARCHAR(100) | None | Yes | None | Supplier's contact email address. |
| phone_number | VARCHAR(20) | None | Yes | None | Supplier's phone number. |
| address | TEXT | None | Yes | None | Supplier's registered address. |

**Note:** `supplier_id` is the primary key. A supplier can be associated with multiple supplier orders. Each supplier order must reference exactly one valid registered supplier.

## 4. SupplierOrder

| Attribute Name | Data Type | Key Type | Nullable | Default Value | Description / Business Rules / Constraints |
|---|---|---|---|---|---|
| order_id | VARCHAR(10) | PK | No | None | Unique identifier for each supplier order. |
| supplier_id | VARCHAR(10) | FK | No | None | References `Supplier(supplier_id)`. Each order must belong to exactly one registered supplier. |
| order_date | DATE | None | No | None | Date when the supplier order is created. |
| status | VARCHAR(20) | None | No | 'Pending' | Order status. Allowed values: Pending, Completed, Canceled. |
| total_amount | DECIMAL(12,2) | None | No | 0 | Total order amount. Must be greater than or equal to 0. Calculated from order details. |

**Note:** `order_id` is the primary key, and `supplier_id` is a foreign key referencing `Supplier(supplier_id)`. Each supplier order must contain at least one SupplierOrderDetail record. The `total_amount` must equal the sum of `order_quantity * unit_price` across all associated SupplierOrderDetail records and must remain consistent when order details are inserted, updated, or deleted. The order status is restricted to Pending, Completed, or Canceled. A Pending order may transition to Completed or Canceled.

## 5. Shipment

| Attribute Name | Data Type | Key Type | Nullable | Default Value | Description / Business Rules / Constraints |
|---|---|---|---|---|---|
| shipment_id | VARCHAR(10) | PK | No | None | Unique identifier for each shipment. |
| tracking_number | VARCHAR(50) | None | No | None | Unique tracking number assigned to the shipment. |
| source_warehouse_id | VARCHAR(10) | FK | No | None | References `Warehouse(warehouse_id)`. Identifies the source warehouse. |
| dest_warehouse_id | VARCHAR(10) | FK | No | None | References `Warehouse(warehouse_id)`. Identifies the destination warehouse. |
| dispatch_date | DATETIME | None | No | None | Date and time when the shipment is dispatched. |
| estimated_arrival | DATETIME | None | No | None | Expected arrival date and time. Must be greater than or equal to `dispatch_date`. |
| status | VARCHAR(20) | None | No | 'Pending' | Shipment status. Allowed values: Pending, In-Transit, Completed, Canceled. |

**Note:** `shipment_id` is the primary key. Both `source_warehouse_id` and `dest_warehouse_id` are foreign keys referencing `Warehouse(warehouse_id)`. The source and destination warehouses must be different. `estimated_arrival` must be greater than or equal to `dispatch_date`. The shipment status is restricted to Pending, In-Transit, Completed, or Canceled. A shipment may transition from Pending to In-Transit or Canceled, and from In-Transit to Completed.

## 6. Inventory

| Attribute Name | Data Type | Key Type | Nullable | Default Value | Description / Business Rules / Constraints |
|---|---|---|---|---|---|
| warehouse_id | VARCHAR(10) | PK, FK | No | None | References `Warehouse(warehouse_id)`. Identifies the warehouse storing the product. |
| product_id | VARCHAR(10) | PK, FK | No | None | References `Product(product_id)`. Identifies the stored product. |
| quantity_on_hand | INT | None | No | 0 | Current quantity of the product in the warehouse. Must be greater than or equal to 0. |
| last_updated | DATETIME | None | No | CURRENT_TIMESTAMP | Date and time when the inventory record was last updated. |

**Note:** The combination of `warehouse_id` and `product_id` forms the composite primary key. Both attributes are also foreign keys referencing Warehouse and Product, respectively. A product can be stored in multiple warehouses, and the inventory quantity (`quantity_on_hand`) must never be negative.

## 7. ProductStructure

| Attribute Name | Data Type | Key Type | Nullable | Default Value | Description / Business Rules / Constraints |
|---|---|---|---|---|---|
| parent_product_id | VARCHAR(10) | PK, FK | No | None | References `Product(product_id)`. Identifies the parent product. |
| child_component_id | VARCHAR(10) | PK, FK | No | None | References `Product(product_id)`. Identifies a component of the parent product. |
| quantity_required | INT | None | No | None | Quantity of the child component required to produce one unit of the parent product. Must be greater than 0. |

**Note:** The combination of `parent_product_id` and `child_component_id` forms the composite primary key. Both attributes are foreign keys referencing `Product(product_id)`. A product can consist of multiple child components, and a child component can belong to multiple parent products. The constraint `parent_product_id <> child_component_id` prevents direct self-reference. However, preventing indirect cycles requires additional validation beyond a simple CHECK constraint, as specified in BR-202.

## 8. SupplierOrderDetail

| Attribute Name | Data Type | Key Type | Nullable | Default Value | Description / Business Rules / Constraints |
|---|---|---|---|---|---|
| order_id | VARCHAR(10) | PK, FK | No | None | References `SupplierOrder(order_id)`. Identifies the supplier order. |
| product_id | VARCHAR(10) | PK, FK | No | None | References `Product(product_id)`. Identifies the ordered product. |
| order_quantity | INT | None | No | None | Quantity of the product ordered. Must be greater than 0. |
| unit_price | DECIMAL(10,2) | None | No | None | Actual purchase price per unit for this specific order. Must be greater than or equal to 0. |

**Note:** The combination of `order_id` and `product_id` forms the composite primary key. Both attributes are foreign keys referencing SupplierOrder and Product, respectively. Each supplier order must contain at least one detail record, and `order_quantity` must be greater than 0. The `unit_price` represents the actual purchase price for that specific supplier order and may differ from `Product.unit_price`.

## 9. ShipmentDetail

| Attribute Name | Data Type | Key Type | Nullable | Default Value | Description / Business Rules / Constraints |
|---|---|---|---|---|---|
| shipment_id | VARCHAR(10) | PK, FK | No | None | References `Shipment(shipment_id)`. Identifies the shipment. |
| product_id | VARCHAR(10) | PK, FK | No | None | References `Product(product_id)`. Identifies the shipped product. |
| shipped_quantity | INT | None | No | None | Quantity of the product included in the shipment. Must be greater than 0. |

**Note:** The combination of `shipment_id` and `product_id` forms the composite primary key. Both attributes are foreign keys referencing Shipment and Product, respectively. Each shipment must contain at least one detail record, and `shipped_quantity` must be greater than 0.

## 10. RestockAlert

| Attribute Name | Data Type | Key Type | Nullable | Default Value | Description / Business Rules / Constraints |
|---|---|---|---|---|---|
| alert_id | VARCHAR(10) | PK | No | None | Unique identifier for each restock alert. |
| warehouse_id | VARCHAR(10) | FK | No | None | Part of a composite foreign key referencing `Inventory(warehouse_id, product_id)`. |
| product_id | VARCHAR(10) | FK | No | None | Part of a composite foreign key referencing `Inventory(warehouse_id, product_id)`. |
| alert_date | DATETIME | None | No | CURRENT_TIMESTAMP | Date and time when the restock alert is created. |
| status | VARCHAR(20) | None | No | 'Pending' | Alert status. Allowed values: Pending, Resolved. |

**Note:** `alert_id` is the primary key. The combination of `warehouse_id` and `product_id` forms a composite foreign key referencing `Inventory(warehouse_id, product_id)`, ensuring that each alert is associated with an existing inventory record. A restock alert is created when the inventory quantity of a product in a warehouse falls below the product's `min_reorder_level`. The alert status is restricted to Pending or Resolved.
